# Unit 1: Software Testing Basics — Mental Model

## How the Topics Connect

```
Testing as Activity/Process
        |
        v
Verification & Validation
        |
        v
V-Model  ←→  STLC (phases + roles)
        |
        v
Basic Definitions (error → fault → defect → failure)
        |
        v
Testing Principles  +  Tester's Role in Org
        |
        v
Reviews (Inspection / Walkthrough)  →  Review Metrics
        |
        v
Test Driven Development (TDD)
```

Think of it as a story:
- First, understand WHAT testing is and WHY we do it
- Then understand the PROCESS models (V-Model, STLC)
- Then nail the VOCABULARY (the definitions QB loves to ask)
- Then the PRINCIPLES that guide all testing
- Then WHO does testing and HOW (tester roles, reviews)
- Finally TDD which flips the traditional process upside-down

## Topic Groups

### Group 1 — What is Testing (01)

- Testing as a process

### Group 2 — Process Models (02)

- STLC phases

### Group 3 — The Vocabulary (03)
- Error → Fault → Defect → Failure chain
- Test case, test suite, test bed, test oracle, test harness
- Software quality and SQA group

### Group 4 — Principles + Roles (04)
- 7 testing principles
- Tester's role in a development organisation
- Agile vs traditional tester role

### Group 5 — Reviews (05)
- Inspection (formal, checklist-driven)
- Walkthrough (informal, author-led)
- Review policies and plans
- Review metrics

### Group 6 — TDD (06)
- Red-Green-Refactor cycle
- Writing tests before code
- Benefits and challenges
